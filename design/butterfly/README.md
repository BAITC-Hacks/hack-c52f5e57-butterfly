# Butterfly: дизайн сайта

**Основной файл:** [butterfly-website-design.pdf](output/pdf/butterfly-website-design.pdf)

Визуальный дизайн, а не реализация frontend. Подготовлен по уточнению владельца
«дизайн в PDF». Все встречи и участники вымышлены. Активная разработка приложения
ведётся отдельно; этот пакет добавляет только `design/butterfly/`.

## Состав

1. Проверка поручений: цитаты, таймкоды, ответственные, сроки и ручное подтверждение.
2. Встречи и загрузка записи: вход в сценарий, список встреч, поиск и статусы.
3. Дизайн-система: цвета, типографика, компоненты, адаптация и правила интеграции.

- `assets/01-meeting-review.png`, `assets/02-meetings-upload.png`: исходные визуальные макеты, 1536 × 1024.
- `tokens.json`: точные проектные значения для реализации. Если растровый макет
  визуально отличается, ориентироваться на токены и текст третьей страницы PDF.
- `PROMPTS.md`: полные промпты встроенного imagegen; второй экран использует первый как референс.
- `build_pdf.py`: воспроизводимая сборка PDF через ReportLab; это инструмент документации.

## Как подхватить в другой сессии

Ветка: **`codex/site-mockup`**. Основана на `main` (`cb942f3`), содержит один
добавочный коммит с этим каталогом. Не заменять рабочую ветку разработки.

```bash
git fetch origin codex/site-mockup
git cherry-pick origin/codex/site-mockup
```

Cherry-pick добавит только дизайн. Существующие frontend, backend, README и общий
план не изменяются. Перед реализацией прочитать PDF и `tokens.json`; переносить
компоненты в выбранный активной сессией стек, не встраивать PNG вместо интерфейса.

## Поведение и Nemotron

NVIDIA Nemotron - основной провайдер проекта. Надпись «Не подключён» в макете
показывает вариант состояния; это не диагноз текущей VM. В реализации статус,
модель, прогресс и ошибки должны приходить от backend. Не добавлять имитацию
успешного inference и не считать нарисованный статус проверкой готовности.

- Пустые владелец и срок остаются пустыми, пока пользователь их не подтвердит.
- Таймкод открывает соответствующий фрагмент записи/стенограммы.
- Кнопка экспорта предлагает реальные PDF/DOCX после проверки результата.
- Fly и Telegram получают события backend. В этом пакете они не реализованы.
- RU/KK на экране - метаданные синтетического примера, не заявление о качестве ASR.
- Текст «файл остаётся в вашем контуре» допустим только для фактического закрытого
  развёртывания. Для публичного Brev-демо заменить на «Обработка на сервере проекта».
- Демо-метка сохраняется при fixture/manual режиме; имена синтетические.

## Адаптация

Desktop от 1280 px: sidebar 224 px, справа контекст 288 px, основной блок fluid.
768-1279 px: sidebar 72 px, контекст после поручений. До 768 px: скрываемая
навигация, один столбец, список встреч карточками, поля и кнопки на всю доступную
ширину. Мобильный экран описан правилами; отдельный мобильный макет не отрисован.

Цвет дополняется текстом и иконкой. Минимальная зона нажатия 44 px. Focus ring
виден на всех интерактивных элементах. Проверить контраст и клавиатурную навигацию
при реализации; растровая иллюстрация не подтверждает доступность frontend.

## Пересборка PDF

Python 3 + `reportlab`, шрифты Noto Sans Regular/Bold в
`/usr/share/fonts/truetype/noto/`. При другом окружении изменить `FONT_ROOT`.

```bash
python3 design/butterfly/build_pdf.py
pdftoppm -scale-to 1600 -png \
  design/butterfly/output/pdf/butterfly-website-design.pdf /tmp/butterfly-design
```

PDF содержит два растровых экрана и страницу с векторным текстом; это не Figma
и не редактируемые слои интерфейса. Веса моделей, токены, реальные записи и
стенограммы в пакет не включены. PNG и PDF не требуют внешних шрифтов или CDN.

## Проверка

Сборка ReportLab; проверка структуры PDF, кириллицы и размеров изображений;
визуальная проверка всех трёх страниц после рендеринга Poppler. Runtime, API и
качество Nemotron не проверялись: изменений приложения в этой ветке нет.

Общий план не обновлялся: им управляет активная сессия разработки. Использован
отдельный локальный clone, поскольку `hackalem-ctl` здесь отсутствует.
